# Constitución del Proyecto Wabbott Panel

1. **Spec-first**: todo cambio nace de `/sdd-spec` → `/sdd-plan` → `/sdd-tasks` → `/sdd-implement`. Nada se implementa sin spec aprobada.
2. **Stack simple**: el panel (`src/`) es HTML, CSS y JavaScript con módulos ES. Sin frameworks, sin TypeScript, sin Tailwind y sin paso de compilación. Cero dependencias de ejecución en el panel. El servidor (`server/`) puede tener dependencias solo si la spec de la tarea las aprueba por escrito, fijadas con `package-lock.json` y revisadas con `npm audit`. Las herramientas de desarrollo son solo las de Node (`node --test`) y las que se aprueben por escrito.
3. **Arquitectura con fronteras**: la lógica pura vive en `src/domain` (sin DOM; la hora actual entra siempre como parámetro) y la comparten el panel y el servidor. Los datos ficticios viven en `src/mock`. La interfaz solo lee y escribe datos a través de `src/services`. La interfaz vive en `src/ui`. El panel habla únicamente con el servidor, nunca directo con la base de datos.
4. **Tests**: la lógica pura, el servicio simulado y el servidor se prueban con `node --test`. La interfaz se valida en navegador a 360, 390 y 1280 px. Una tarea no está hecha si sus pruebas fallan. Todo endpoint lleva pruebas de seguridad (acceso a otro negocio, entrada inválida, falta de sesión).
5. **Datos y seguridad**: en el repositorio solo hay datos ficticios. Ningún secreto, token ni dato real en el navegador ni en el repositorio. Los datos reales viven solo en la base de datos. Los textos de clientes se insertan con `textContent`, nunca como HTML.
6. **Idioma**: textos de interfaz en español de México; nombres de variables, funciones y archivos en inglés.
7. **Base de datos**: los cambios se hacen solo con migraciones SQL numeradas en `migrations/`, aditivas e idempotentes, y se prueban primero en el proyecto de pruebas. Nada se borra sin decirlo en la spec.
